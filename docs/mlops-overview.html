MLOps pipeline overview

How the models are fine-tuned on your data and reach production: real checks from the officers go in, a pretrained model is fine-tuned, proven against the current one, approved by a person, and released as one versioned bundle that can be rolled back.

  1. 1

    Collect

    Jobs the officers checked in Parcel: photo, what the OCR read, what the officer saved.

  2. 2

    Curate and label

    Remove duplicates and bad photos, review a sample, mark label corners where needed.

  3. 3

    Version the data

    Every dataset and split is a version. Test sets are real photos, frozen, never trained on.

    GitDVCMinIO
  4. 4

    Fine-tune

    Fine-tune pretrained models on your own labels, on a GPU server, in a container, on a chosen data version.

    Docker
  5. 5

    Evaluate and gate

    Score the new model against the current one on the frozen tests. Calibrate confidence. Pass or stop.

    MLflow
  6. 6

    Register and shadow

    Keep it as challenger, run it next to the live model, a named person approves.

    MLflowPostgreSQL
  7. 7

    Release and monitor

    Ship one versioned bundle. Watch correction rate and drift. Roll back to the previous bundle if needed.

    DockerHarbor
Feedback loop: corrections that officers make in production and signs of drift go back to step 1, and decide when the next training run is worth starting.

Tech stack

GitDVCMLflowMinIOPostgreSQLDockerHarbor

DVC versions the data and defines the pipeline stages. MLflow tracks experiments and holds the model registry (champion and challenger). Object storage holds datasets and bundles; PostgreSQL backs MLflow; Docker runs the jobs; a registry holds the release images. All on-prem.
